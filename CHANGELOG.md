# Changelog

## Unreleased

### Added

- A web console at `/console` for every role. Admins get overview, tools (pins, diffs, scanner
  findings, approve and quarantine), approvals, the full audit log with chain verification and
  CSV export, API key management and the policy in force with reload. Every other role gets
  their own overview, a playground limited to their own roles, their own activity and their
  own approval requests. Roles are enforced per route on the server.
- The playground runs calls through the same pipeline instance as `/mcp`, so they are decided,
  rate-limited, held for approval and audited exactly like a client's, marked
  `auth_method=console`.

## v0.1.1 - 2026-11-14

### Fixed

- `files__list_files {}` was refused although the tool declares `path` optional with a default
  of `"."`: a policy constraint on an absent argument fails closed. A new `defaults` stage, after
  definition integrity and before policy, fills an omitted top-level argument from the pinned
  schema's non-null default; policy checks the filled value and the upstream receives exactly
  that value. An upstream whose declared default violates a constraint is refused, as before.
  Found by the soak test. The red-team suite gained the two benign cases it was missing.

## v0.1.0 - 2026-11-14

The first public release: a working MCP security gateway with every layer the design calls
for, a red-team suite, a latency benchmark, a soak test, and a threat model whose every
mitigation names the test that proves it.

### What is in it

- Streamable HTTP gateway in front of stdio and HTTP MCP upstreams, with namespaced tools
  (`<server>__<tool>`) and protocol revision 2026-07-28.
- API-key and ES256 JWT authentication with rotation, revocation and JWKS; no token passthrough.
- Deny-by-default policy with argument constraints and safe hot reload.
- Atomic Redis rate limits, daily and destructive budgets, result size caps.
- SHA-256 pinning of tool definitions, rug-pull and poisoning quarantine, admin approval of
  untrusted servers.
- Injection scanning of definitions and results, DLP on arguments, an optional local classifier
  pinned to a model commit.
- Single-use, argument-bound human approvals with a CSRF-protected, strict-CSP web UI.
- Insert-only, hash-chained audit log with write-ahead fail-closed semantics and
  `warden audit verify`.
- OpenTelemetry traces, Prometheus metrics and a Grafana dashboard.
- A local demo agent (Ollama, or a scripted model for CI) and five attack scenarios.
- A non-root, read-only-root container image with a `WITH_ML` build arg; `make up-all` runs the
  whole stack.

### Hardening in this release

- Request bodies capped and refused with 413 before parsing; JSON-RPC batches refused.
- Explicit socket and statement timeouts on Redis and Postgres, so a hung dependency denies
  instead of hanging.
- CSP, `X-Frame-Options`, `Referrer-Policy`, `nosniff` and `no-store` on the approval UI.
- RFC 9728 protected-resource metadata served at the path-aware location.
- Every compose port published on loopback only.
- bandit clean (two justified suppressions); pip-audit clean after upgrading `cryptography`.
- No literal invisible or bidi characters anywhere in the source tree.

### Known gaps

See [docs/threat-model.md](docs/threat-model.md#known-gaps). In short: the classifier is weak
and ships off; rules only catch what they were written for; no OAuth authorization server;
single node; stdio upstreams run as the gateway's user; a constraint on an absent optional
argument denies (fixed in v0.1.1).
